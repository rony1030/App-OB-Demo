# Proposal creator

Scope: `/portal/proposals/new`, operating surface for authenticated brokers on desktop and mobile.

Audience and task: A broker selects a registered CRM lead, confirms previously selected units, reviews the generated proposal, saves it and shares the immutable result. Success is a finished proposal without manual page design.

Content and constraints: Use real project, inventory, developer brand and CRM data. Preserve server validation, same-developer rules, private expiring links and Letter PDF output. The dossier editor remains untouched. Full-page images have no folded-corner ornament.

## Direction contract

THESIS: A short commercial sequence produces a finished proposal; the surface refuses the freeform canvas and its pages, blocks, media and design panels.

OWN-WORLD: Existing OB Brokers operational UI—white surfaces, navy ink, restrained project accent—with the generated document carrying the developer’s official identity and Cana Rock editorial structure.

STORY: Confirm units, select the CRM recipient, make only essential cover/message choices, review exact pages, then save and share.

FIRST VIEWPORT: Desktop places a compact configuration column beside one complete Letter page. Mobile places the same controls above the exact desktop Letter composition scaled to the available width, with page navigation outside the sheet.

FORM: User-pinned Cana Rock proposal flow, seed key `user-pinned-cana-rock-proposal-v1`.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

Unresolved: Future phases may add controlled payment-plan alternatives. V2 uses project truth and does not expose that complexity.
